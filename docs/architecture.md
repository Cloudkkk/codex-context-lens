# Architecture

## 数据与界面路径

```text
Setup 初始化 / 可选 SessionStart hook
       │
       ▼
Python supervisor ── reads ── ~/.codex/sessions/**/*.jsonl
       │                          │
       │                          ▼
       │                    SessionStore / reader
       │                          │
       ▼                          │
Loopback CDP ◀─────────────────────┘
       │
       ▼
Message action button → hover panel
```

没有 MCP 聊天查询工具或远程后端。开发用的 HTML 预览使用模拟数据，运行时不需要 HTTP 预览服务器。

## 文件分工

| 文件 | 职责 |
| --- | --- |
| `reader.py` | 扫描 rollout，重建历史，读取用量与生成分类估算 |
| `cdp.py` | 标准库 WebSocket/CDP 传输，仅接受 loopback 地址 |
| `lifecycle.py` | 识别主应用、检查插件开关、带调试参数打开应用 |
| `initialize.py` | 明确初始化请求、等待轮次完成、正常退出与一次重开 |
| `routing.py` | 增量索引真实轮次到日志会话的归属，处理临时 ID 和歧义 |
| `overlay.py` | 管理监控进程、连接窗口、处理悬停时的数据请求 |
| `matching.js` | Markdown 与渲染文本规范化、唯一轮次匹配、会话 ID 解析 |
| `overlay.js` | 入口、Shadow DOM 面板、交互与虚拟列表重新挂载 |

## 总量与历史轮次

优先读取 `token_usage_record.usage`，兼容 `event_msg.token_count.info.last_token_usage`。总量使用最近一次请求的 `input_tokens`，不是生命周期累计消耗，也不把输出加入输入窗口。

`cached_input_tokens` 是输入子项，`reasoning_output_tokens` 是输出子项；均不重复相加。重复的用量回显不产生新的请求边界。

轮次绑定 `turn_id`、用量行号和完成状态。悬停历史回复时，按该轮最后用量行回放，而不是返回最新轮次的数字。

首条 `session_meta.id` 是 rollout 身份的依据。子代理日志可能重放父会话元数据，不能因此覆盖子会话 ID。

## 压缩与分类

最新的 `compacted.replacement_history` 替代之前的活跃历史。缺少替换历史时，只恢复日志中的摘要与后续条目。

如果最新用量早于压缩事件，该数字不再描述新上下文窗口；插件显示未知，直到出现新的用量记录。

分类按可见文本估算：ASCII 约 4 字符/token，中文约 1 字符/token，其他字符约 2 字符/token。加密内容与图片 base64 长度不会作为 token 估算依据。可见估算超过实际输入时按比例封顶，类别加总保持一致；剩余差异归为日志未覆盖的差额。

分类汇总目前不提供展开入口。后端仍保留归因条目，供以后改进内容解释，而不是在界面展示重复记录。

## 会话与消息匹配

会话 ID 优先来自可见消息输入框，侧栏选中项作为回退。存在多个可见输入框时，不在缺少一致证据的情况下选择会话。

优先读取回复祖先节点的 `data-content-search-turn-key`，用真实 `turn_id` 索引直接查找本会话日志，不读取正文。真实 ID 已存在但日志暂未到达时等待日志，不回退到文本匹配。仅缺少真实 ID 时兼容旧轮次 ID、消息 ID 和唯一短文本签名；不按数组顺序或日志更新时间猜测。

扫描时跳过隐藏的缓存会话；入口紧挨时间左侧。

页面状态同时提供临时/稳定的 UI 标识与可见真实轮次 ID。后端维护共享的增量轮次索引，每个 renderer 单独解析会话；已知轮次归属取交集，复制/分叉造成多义时仅允许精确会话 ID 消歧。缺日志时等待，不使用最新日志或正文猜会话。

数据携带 UI 标识与可见轮次集合生成的视图 token；前端在更新和 hover 回包时校验当前 token，后端也校验悬停请求的会话归属。聊天切换立即失效旧数据，并通知后台重新解析。多窗口共用日志索引但不共用视图状态；诊断按 renderer 显示原始标识、解析后 UUID、路由原因、挂载数与视图 token。状态诊断记录真实 ID 命中、文本回退、未匹配与隐藏候选数量。

完成状态与请求用量缺失、文本过短或重复文案歧义，都可能导致某条回复没有入口。

## 进程与桌面生命周期

监控状态与日志位于系统临时目录 `codex-context-lens-<uid>`。启动锁与进程校验防止重复 hook 创建多个监控；新版本会先停止旧版监控再接入窗口。

只有用户执行 initialize 才创建重启请求；Hook 只启动监控。初始化通过 CODEX_THREAD_ID 确认当前聊天和活跃轮次，不猜测 latest。等待当前轮次以及最近 24 小时日志中可见的本地活跃轮次完成，连续空闲至少 3 秒后，通过 NSRunningApplication.terminate 请求正常退出，再用 open 带 loopback 调试参数重开。聊天同一时刻只有一个活跃轮次，后续轮次覆盖中断的历史轮次。日志不完整、进程身份变化、等待 15 分钟或退出 30 秒超时时取消，不强退、不重试循环。

成功连接后正常退出应用不会触发重开。插件关闭或监控停止会取消待执行的重开。纯 CLI 场景没有运行的桌面实例时，不自动打开 GUI。

## 验证边界

自动测试覆盖合成日志、传输、匹配与模拟进程状态。UI 使用同一份代码在模拟页面验证，基础 hover 也经过用户在实际桌面端确认。

CI 不访问真实用户 sessions，不启动或操作 Codex 桌面端。桌面应用升级后的选择器兼容性、深色模式和真实重开流程仍需要手动检查。
